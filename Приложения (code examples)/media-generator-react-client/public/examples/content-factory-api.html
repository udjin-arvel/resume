ContentFactory API — справочник и песочница

Основное приложение radar-art__client ходит в бэкенд по REST (RTK Query). ContentFactory (проекты, ноды, рёбра графа, генерация, события) доступен по GraphQL на маршруте /graphql в FastAPI. Эта страница — статический справочник с копируемыми примерами и простыми запросами из браузера.

1. Связь с текущим React-клиентом

В коде клиента токен берётся из cookie radar и в REST передаётся как заголовок Authorization: JWT <токен> (prepareHeaders в rtk-api.ts). Для GraphQL используйте тот же JWT в том же формате. Альтернатива для части сценариев бэкенда: Authorization: Bearer <token> (см. app/graphql/auth.py).

Контекст авторизации в SPA: AuthContext читает cookie radar через useCookie('radar'). Для ручных тестов ниже вставьте сырое значение токена (без префикса JWT).

2. Настройки запросов

Прокси. REST в клиенте по умолчанию с суффиксом /api (VITE_API_URL), а роутер GraphQL в приложении смонтирован как /graphql от корня FastAPI. В проде путь снаружи может быть https://хост/graphql или https://хост/api/graphql — уточните по своему nginx / ingress.

CORS. Если эта страница открыта с другого origin, чем API, браузер может блокировать fetch и WebSocket. Держите фронт и API на одном сайте или настройте прокси dev-сервера.

3. HTTP: операции из браузера

Тело: JSON с полями query и при необходимости variables. Заголовки: Content-Type: application/json, Authorization: JWT ….

Обновить AI-модель ноды (aiModel)

      

        Идентификатор модели хранится в колонке БД ноды и при generateContentFactoryNode попадает в Task и Kafka.
        Поле aiModel в JSON data для выбора модели не используется — задавайте модель через create/update ниже.
      

      


      
Обновить промпт ноды (updateContentFactoryNodePrompt)

      

        Текст — колонка ContentFactoryNode.prompt; после мутации status сбрасывается в idle. Поле prompt внутри только JSON data не используйте как источник истины.

      


      
Обновить aspectRatio ноды (updateContentFactoryNodeAspectRatio)

      

        Колонка aspect_ratio задаёт формат для следующей генерации (в т.ч. в Kafka-options). Допустимые строки зависят от выбранной aiModel.

      


      

        Дефолтные модели (aiModel). Для нод GENERATED_CONTENT при создании/генерации, если aiModel не задан, бэкенд выбирает модель по taskType в data или по contentType (IMAGE → edit_image, VIDEO → video_preview).
        Кодовые дефолты: image — google/nano-banana-2/edit, video preview — google/veo3.1/image-to-video; переопределение через env CONTENT_FACTORY_MODEL_EDIT_IMAGE, CONTENT_FACTORY_MODEL_VIDEO_PREVIEW и др. (см. backend/.env.example).
        Поле aiModel в JSON data не используется — только колонка ноды (create / updateContentFactoryNodeAiModel). Аналогично prompt и aspectRatio задаются топ-полями и мутациями выше, а не дублем внутри data.
      


      

        Stale-рёбра. После успешной генерации ноды N (node.result_ready, Kafka или cache hit):
        исходящие N → * → stale; входящие * → N, которые уже были stale, → active (перегенерация downstream на актуальных входах).
        Не срабатывает при правке prompt/data/upload без успешного run. В payload node.result_ready: edges_staled, edges_reactivated (массивы { edge_id, source_node_id, target_node_id }).
        Пока нода не отгенерилась с новым контекстом, downstream остаётся active.
        Для ноды GENERATED_CONTENT при generateContentFactoryNode промпт и референсы собираются с входящих USER_CONTENT.
        Загрузка референса: multipart POST .../content-factory/nodes/{id}/image или .../video, поле file.
        Превью проекта (скриншот канваса): multipart POST .../content-factory/projects/{projectId}/preview, поле file — обновляет previewPath / previewThumbnailPath проекта.
      

    


    

      
5. WebSocket: подписка contentFactoryEvents

      

        Протокол — graphql-ws (поддерживается Strawberry вместе с legacy). Удобная библиотека клиента —
        graphql-ws.
        URL WebSocket тот же путь, что и HTTP GraphQL, со схемой ws: / wss:.
      


      

        Авторизация из браузера. Произвольные HTTP-заголовки при открытии WebSocket задать нельзя; токен передаётся в
        connectionParams (graphql-ws). Бэкенд подставляет пользователя из
        Authorization в этих параметрах при выполнении подписок.
      


      

        Анонимный или авторизованный viewer публичного проекта может подписаться на contentFactoryEvents без токена (для приватного проекта нужен владелец или публикация).
      


      

        Payload событий. В payload подписки для операций с нодами приходит полный снимок (ключи в snake_case):
        node_id, project_id, type, pin_type, content_type, prompt, path, path_thumbnail,
        position_x, position_y, z_index, data, status, result_url, result_url_thumbnail,
        cache_key, ai_model, aspect_ratio (соотношение сторон, колонка), last_task_id, updated_at,
        опционально вложенный объект generation (то же содержание, что в GraphQL-подполях генерации — в snake_case: id, status, prompt, reference, reference_thumbnails, result, result_thumbnail, created_at, completed_at, generation_timings),
        плюс action (node_created, node_duplicated, node_prompt_updated, node_aspect_ratio_updated, …).
        result_url_thumbnail — превью результата генерации (для IMAGE); путь вида /storage/{userId}/thumbnails/…, для VIDEO и внешних URL — null.
        Для прогона генерации дополнительно: node_run_id, node_run_status, task_id, generation_id, cached, error.
        generation_id — id записи Generation в БД: в node.status_changed и node.failed (при ошибке enqueue),
        в node.result_ready после Kafka (или из response_payload прогона). При cache hit (cached: true) поля нет — реальная генерация не создавалась.
        При успешной генерации в node.result_ready также: edges_staled, edges_reactivated.
        При дублировании: source_node_id. Исключение: node_deleted — только project_id, action, node_id.
        Первое сообщение подписки: eventType: "connected".
