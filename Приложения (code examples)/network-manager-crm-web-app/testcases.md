# Тест-кейсы Radar CRM

## Предусловия

- Установлены Go 1.24+, Node.js 22+, Docker и Docker Compose.
- Созданы `.env`, `backend/.env`, `client/.env` по примерам из README.
- Запущены PostgreSQL и API: `docker compose up -d`.
- Применены миграции backend.
- Frontend запущен из `client`: `npm install`, затем `npm run dev`.
- Проверены базовые URL:
  - API health: `http://localhost:8080/health`;
  - Frontend: `http://localhost:3000`;
  - API base: `http://localhost:8080/api/v1`.
- Создан активный менеджер, например seed-пользователь `admin@example.com` / `admin12345`.
- Для проверки worker-сценариев подготовлен или зарегистрирован работник, заполнен onboarding и одобрен менеджером.

## 1. Запуск и базовая доступность

- Открыть `http://localhost:8080/health`.
  - Ожидаемо: API отвечает успешным JSON со статусом health.
- Открыть `http://localhost:3000`.
  - Ожидаемо: неавторизованный пользователь перенаправляется на `/auth/login`.
- Открыть несуществующий путь, например `/unknown-page`.
  - Ожидаемо: показывается страница 404 с кнопкой перехода на главную.
- Остановить backend и обновить frontend-страницу с данными.
  - Ожидаемо: в разделах с API-запросами показывается состояние ошибки и кнопка повтора, приложение не падает целиком.

## 2. Авторизация менеджера

- На `/auth/login` войти под `admin@example.com` / `admin12345`.
  - Ожидаемо: пользователь попадает на главную менеджера `/`.
- Проверить, что в `localStorage` появился ключ `crm_token`.
  - Ожидаемо: токен сохранён и используется в последующих API-запросах.
- Обновить страницу после входа.
  - Ожидаемо: сессия сохраняется, повторный ввод логина не нужен.
- Очистить `crm_token` в браузере и открыть `/`.
  - Ожидаемо: происходит редирект на `/auth/login`.
- Ввести неправильный пароль.
  - Ожидаемо: вход не выполняется, пользователь видит ошибку.

## 3. Регистрация и onboarding работника

- Открыть `/auth/register`.
- Зарегистрировать нового пользователя с валидным email, паролем от 8 символов, именем, фамилией и телефоном.
  - Ожидаемо: создаётся worker-пользователь, выполняется вход, пользователь направляется на onboarding или ожидание подтверждения.
- На onboarding заполнить должность (select), сертификаты (multi-select, минимум 1), ставку, загрузить паспорт (через экран с примером фото) и другие обязательные поля.
  - Ожидаемо: в документах только паспорт (обязательно) и права; профиль сохраняется, пользователь переходит на `/pending-approval`.
- На `/pending-approval` нажать обновление статуса.
  - Ожидаемо: пока менеджер не одобрил пользователя, экран ожидания остаётся.
- Выйти из аккаунта с экрана ожидания.
  - Ожидаемо: пользователь попадает на `/auth/login`, токен удалён.
- Проверить выход из профиля/экрана ожидания при недоступном `POST /auth/logout`.
  - Ожидаемо: даже если backend возвращает ошибку или endpoint недоступен, frontend очищает локальный `crm_token` и пользователь выходит из сессии.

## 4. Доступ по ролям

- Под менеджером открыть `/worker`.
  - Ожидаемо: менеджера перенаправляет обратно в менеджерскую зону `/`.
- Под работником открыть `/`.
  - Ожидаемо: работника перенаправляет в `/worker`.
- Под pending-работником открыть `/worker`.
  - Ожидаемо: пользователь перенаправляется на onboarding или `/pending-approval`.
- Под неавторизованным пользователем открыть `/projects`, `/workers`, `/finance`, `/worker/projects`.
  - Ожидаемо: все защищённые маршруты ведут на `/auth/login`.

## 5. Главная менеджера

- Войти менеджером и открыть `/`.
  - Ожидаемо: отображается заголовок главной, дата, быстрые действия, срочные действия и последняя активность.
- Нажать быстрые действия: создать проект, добавить работника, создать смету, добавить инструмент.
  - Ожидаемо: пользователь переходит в соответствующий раздел или открывается соответствующая форма.
- Открыть диалог ручного уведомления.
  - Ожидаемо: доступны поля UUID пользователя, заголовок и текст.
- Попробовать отправить уведомление с пустыми полями.
  - Ожидаемо: отправка не выполняется.
- Заполнить валидный UUID пользователя, заголовок и текст, отправить.
  - Ожидаемо: показывается успешное уведомление, диалог закрывается.
- Переключить фильтры срочных действий.
  - Ожидаемо: список и счётчики фильтруются без перезагрузки страницы.

## 6. Клиенты и проекты

- Открыть `/projects`.
  - Ожидаемо: отображается список проектов, поиск, фильтры статусов и фильтр по клиенту.
- Переключиться на вкладку клиентов.
  - Ожидаемо: отображается список клиентов и кнопка создания клиента.
- Создать клиента с уникальным названием.
  - Ожидаемо: клиент появляется в списке и доступен в фильтрах проектов.
- Вернуться к проектам и создать проект.
  - Ожидаемо: проект сохраняется, появляется в списке и открывается в карточке или доступен по ссылке.
- Проверить поиск проекта по названию или локации.
  - Ожидаемо: список фильтруется по введённой строке.
- Проверить фильтры `Все`, `Активные`, `Завершённые`, `Архив`.
  - Ожидаемо: отображаются только проекты выбранного статуса.
- Открыть карточку проекта.
  - Ожидаемо: отображаются обзор, базовая информация, статистика, проблемы и вкладки проекта.
- Изменить название, локацию и даты проекта через «Изменить проект» или inline в основной информации.
  - Ожидаемо: изменения сохраняются и видны после обновления страницы.
- Закрыть активный проект кнопкой «Закрыть проект».
  - Ожидаемо: статус «Завершён», баннер read-only, кнопки редактирования и назначения скрыты.
- На вкладке работников проекта отправить напоминание работнику.
  - Ожидаемо: показывается сообщение об успешной отправке или понятная ошибка.

## 7. Работники

- Открыть `/workers`.
  - Ожидаемо: отображаются вкладки `Заявки`, `Активные`, `Отклонённые`, `Архив`, `Ресурсы`.
- Найти зарегистрированного pending-работника.
  - Ожидаемо: он отображается во вкладке ожидания.
- Открыть карточку pending-работника и одобрить его.
  - Ожидаемо: статус меняется на active, работник появляется во вкладке действующих.
- Отклонить pending-заявку с причиной и комментарием.
  - Ожидаемо: работник может войти, видит `/application-rejected` с причинами; может повторно отправить заявку через onboarding → статус снова pending.
- Вернуть заявку на доработку (return).
  - Ожидаемо: работник видит список исправлений на `/pending-approval`, может исправить через onboarding; reject и return ведут себя по-разному.
- Заблокировать действующего работника.
  - Ожидаемо: статус меняется на blocked, работник появляется во вкладке архива; login разрешён, доступ только к профилю.
- Разблокировать работника.
  - Ожидаемо: статус возвращается в active, полный доступ восстанавливается.
- Удаление аккаунта работника.
  - Ожидаемо: **не реализовано** (API/UI отсутствуют); снятие с проекта не удаляет аккаунт.
- Проверить поиск по имени и специализации.
  - Ожидаемо: список работников фильтруется.
- Проверить фильтр по специализациям.
  - Ожидаемо: показываются только работники выбранной группы.
- Открыть вкладку ресурсов.
  - Ожидаемо: видны суммарные показатели и загрузка по специализациям.

## 8. Сметы

- Открыть `/estimates`.
  - Ожидаемо: отображаются вкладки черновиков, отправленных, согласованных и отклонённых смет.
- Создать новую смету.
  - Ожидаемо: открывается редактор `/estimates/new`.
- Заполнить основную информацию: название, компанию, контакт, телефон, email, страну, город.
  - Ожидаемо: поля редактируются без ошибок.
- Добавить блок услуг, заполнить позицию, количество, единицу и цену.
  - Ожидаемо: сумма блока и итог сметы пересчитываются.
- Добавить блок ресурсов и блок дополнительных расходов.
  - Ожидаемо: блоки добавляются, итог обновляется.
- Переместить блоки вверх/вниз и удалить один блок.
  - Ожидаемо: порядок меняется, удалённый блок исчезает, итог пересчитывается.
- Сохранить смету.
  - Ожидаемо: смета появляется в списке черновиков.
- Изменить статус сметы на отправленную, согласованную или отклонённую.
  - Ожидаемо: смета переходит в соответствующую вкладку.
- Сохранить смету как шаблон.
  - Ожидаемо: шаблон появляется в блоке шаблонов для новых смет.
- Создать смету из шаблона.
  - Ожидаемо: новая смета создаётся с блоками шаблона.
- Экспортировать смету в PDF и Excel.
  - Ожидаемо: браузер скачивает файл, ошибок API нет.
- Создать проект из сметы.
  - Ожидаемо: создаётся проект, пользователь переходит в карточку проекта; повторное создание недоступно.
- Согласованную смету с проектом отредактировать и нажать «Сохранить и закрыть».
  - Ожидаемо: название, локация и бюджет связанного проекта синхронизируются; ссылка «Открыть проект» видна вместо кнопки создания.

## 9. Отчёты работников для менеджера

- Открыть `/reports` и выбрать `Отчёты работников`.
  - Ожидаемо: отображается список weekly-отчётов.
- Проверить фильтры по статусу, клиенту, проекту и работнику.
  - Ожидаемо: список фильтруется корректно.
- Открыть отчёт на проверке.
  - Ожидаемо: видны работник, проект, период, часы по дням, описание, расходы и расчёт.
- Принять отчёт.
  - Ожидаемо: статус отчёта меняется на принятый, сумма учитывается в финансах.
- Вернуть другой отчёт без комментария.
  - Ожидаемо: кнопка возврата недоступна или действие не выполняется.
- Вернуть отчёт с комментарием.
  - Ожидаемо: статус меняется на returned, комментарий виден работнику.

## 10. Ежедневные отчёты супервайзеров для менеджера

- В `/reports` выбрать `Отчёты супервайзеров`.
  - Ожидаемо: отображается список daily-отчётов.
- Проверить фильтры по статусу, проекту и супервайзеру.
  - Ожидаемо: список фильтруется корректно.
- Открыть отчёт со статусом объекта `issue`.
  - Ожидаемо: виден блок проблемы на объекте.
- Открыть отчёт со статусом объекта `downtime`.
  - Ожидаемо: видны часы простоя и причина простоя.
- Сохранить комментарий менеджера.
  - Ожидаемо: комментарий сохраняется и отображается после обновления.
- Отметить отчёт как `Требует внимания`.
  - Ожидаемо: статус меняется, отчёт попадает в соответствующий фильтр/срочные действия.
- Принять отчёт.
  - Ожидаемо: статус меняется на принятый.

## 11. Финансы

- Открыть `/finance`.
  - Ожидаемо: отображаются вкладки `Обзор`, `Проекты`, `Работники`, `Категории`.
- Проверить вкладку обзора.
  - Ожидаемо: видны бюджет, выплачено, остаток, активные проекты, расходы по категориям.
- Проверить фильтр по клиенту.
  - Ожидаемо: финансовые списки проектов меняются под выбранного клиента.
- Перейти на вкладку проектов.
  - Ожидаемо: видны бюджеты, расходы и остатки по проектам.
- Перейти на вкладку работников.
  - Ожидаемо: видны начисления по работникам на основе принятых отчётов.
- Перейти на вкладку категорий.
  - Ожидаемо: видна разбивка расходов по категориям.
- Принять новый отчёт работника и вернуться в финансы.
  - Ожидаемо: финансовые суммы обновляются после рефетча/обновления страницы.

## 12. Инструменты

- Открыть `/tools`.
  - Ожидаемо: отображается список инструментов, поиск и вкладки статусов.
- Создать новый инструмент с типом контроля `Калибровка`.
  - Ожидаемо: инструмент появляется в списке доступных.
- Создать новый инструмент с типом контроля `Лимит использований`.
  - Ожидаемо: без лимита форма не сохраняется, с валидным лимитом инструмент создаётся.
- Проверить поиск по названию, серийному номеру и типу.
  - Ожидаемо: список фильтруется.
- Открыть карточку инструмента.
  - Ожидаемо: видны статус, тип, серийный номер, контроль, текущая выдача/калибровка/лимит.
- Назначить инструмент на активный проект.
  - Ожидаемо: статус меняется на `assigned`, блок текущей выдачи показывает проект.
- Вернуть инструмент с проекта.
  - Ожидаемо: статус возвращается в доступный, текущая выдача исчезает.
- Для инструмента с калибровкой записать новую дату `Годен до`.
  - Ожидаемо: запись появляется в истории калибровок, дата обновляется.
- Проверить вкладку `Требуют внимания`.
  - Ожидаемо: там отображаются инструменты с просроченной калибровкой, статусом overdue или лимитом использований 90%+.

## 13. Рабочая зона работника

- Войти активным работником.
  - Ожидаемо: пользователь попадает на `/worker`.
- Проверить главную работника.
  - Ожидаемо: видны приветствие, быстрые действия, активные проекты и возвращённые отчёты.
- Открыть `/worker/projects`.
  - Ожидаемо: отображаются проекты работника.
- Подтвердить ожидающее назначение на проект.
  - Ожидаемо: статус назначения меняется, проект считается подтверждённым.
- Проверить изоляцию сметы при приглашении на проект.
  - Под менеджером на проекте загрузить документ категории «Сметы» и документ категории «Инструкции».
  - Назначить работника на проект (до или после подтверждения участия).
  - Под работником открыть `/worker/projects/:projectId`.
  - Ожидаемо: в списке документов проекта видны инструкции и общие документы, сметы нет.
  - Под работником запросить `GET /api/v1/documents/:id/access-url` для ID сметы.
  - Ожидаемо: API возвращает 403.
  - Под менеджером открыть вкладку «Документы» проекта.
  - Ожидаемо: смета и инструкции видны в соответствующих категориях.
- Открыть `/worker/reports`.
  - Ожидаемо: доступны вкладки еженедельных и ежедневных отчётов.
- Проверить фильтры отчётов по статусу и проекту.
  - Ожидаемо: список фильтруется.
- Открыть `/worker/profile`.
  - Ожидаемо: отображаются персональные данные, статус, должность, специализация, ставка.
- Сменить язык на English и обратно на Русский.
  - Ожидаемо: язык интерфейса меняется и сохраняется в профиле.
- Выйти из профиля.
  - Ожидаемо: пользователь перенаправлен на `/auth/login`, токен удалён.

## 14. Создание weekly-отчёта работником

- Под активным работником открыть `/worker/reports/new`.
  - Ожидаемо: доступен список активных проектов работника.
- Выбрать проект и заполнить часы по дням.
  - Ожидаемо: итог часов пересчитывается.
- Заполнить описание выполненных работ.
  - Ожидаемо: текст сохраняется в форме.
- Добавить дополнительный расход с категорией, суммой и комментарием.
  - Ожидаемо: расход добавляется к отчёту.
- Отправить отчёт.
  - Ожидаемо: отчёт создаётся, пользователь переходит на его детальную страницу, статус `review`.
- Под менеджером открыть этот отчёт.
  - Ожидаемо: менеджер видит все часы, описание и расходы.
- Вернуть отчёт менеджером.
  - Ожидаемо: работник видит отчёт во вкладке возвращённых/со статусом returned.

## 15. Создание daily-отчёта супервайзером

- Под пользователем, назначенным супервайзером проекта, открыть `/worker/daily-reports/new`.
  - Ожидаемо: доступны только проекты, где пользователь является супервайзером.
- Повторить сценарий для пользователя с проектной ролью `supervisor`, но глобальной ролью `worker`.
  - Ожидаемо: результат фиксируется отдельно; если API требует глобальную роль `supervisor`, daily-отчёт должен быть запрещён или не должен успешно создаваться.
- Повторить сценарий для пользователя с глобальной ролью `supervisor`, назначенного супервайзером на проект.
  - Ожидаемо: создание daily-отчёта разрешено.
- Создать отчёт со статусом объекта `ok`.
  - Ожидаемо: отчёт создаётся и появляется в daily-списке.
- Создать отчёт со статусом `issue` и описанием проблемы.
  - Ожидаемо: менеджер видит проблему в daily-отчётах и карточке проекта.
- Создать отчёт со статусом `downtime`, указать часы и причину простоя.
  - Ожидаемо: часы простоя видны в отчёте, проекте и финансовом обзоре для проектов по смете.
- Заполнить текстовое описание для транскрипции.
  - Ожидаемо: на детальной странице отображается блок голосового/текстового отчёта с транскрипцией.

## 16. Документы и файлы

- Проверить API загрузки документа через UI, где доступен компонент загрузки, или напрямую через `/api/v1/documents`.
  - Ожидаемо: файл сохраняется, API возвращает созданный документ.
- Скачать загруженный документ по ID.
  - Ожидаемо: файл скачивается или открывается браузером.
- Заменить документ.
  - Ожидаемо: новая версия доступна при скачивании.
- Удалить документ.
  - Ожидаемо: повторное скачивание удалённого документа возвращает ошибку.
- Проверить, что пользователь без токена не может работать с документами.
  - Ожидаемо: API возвращает 401.

## 17. Уведомления

- Под менеджером отправить уведомление существующему пользователю.
  - Ожидаемо: API возвращает успех, уведомление появляется у пользователя в списке уведомлений.
- Получить список уведомлений под пользователем.
  - Ожидаемо: возвращаются только уведомления текущего пользователя.
- Отметить уведомление прочитанным.
  - Ожидаемо: у уведомления появляется `readAt`.
- Проверить отправку при пустом или несуществующем userId.
  - Ожидаемо: API возвращает валидационную ошибку или 404.
- Если настроен `TELEGRAM_BOT_TOKEN`, проверить доставку уведомления в Telegram.
  - Ожидаемо: сообщение приходит в Telegram пользователю с привязанным Telegram ID.

## 18. API и безопасность

- Выполнить запрос к защищённому endpoint без токена, например `GET /api/v1/projects`.
  - Ожидаемо: ответ 401.
- Выполнить запрос с некорректным токеном.
  - Ожидаемо: ответ 401, frontend удаляет `crm_token`.
- Под worker-пользователем вызвать менеджерский endpoint создания/изменения сущности.
  - Ожидаемо: ответ 403 или отказ доступа.
- Отправить некорректные данные в регистрацию: короткий пароль, неверный email, пустое имя.
  - Ожидаемо: ответ 400 с ошибками валидации.
- Повторно зарегистрировать уже существующий email.
  - Ожидаемо: ответ 409 или понятная ошибка конфликта.
- Проверить заголовок `Accept-Language` при смене языка.
  - Ожидаемо: backend получает текущую локаль, ошибки возвращаются на соответствующем языке при наличии переводов.

## 19. Проверка данных после обновления

- Создать клиента, проект, смету, работника, отчёт и инструмент.
- Обновить страницу браузера.
  - Ожидаемо: созданные данные остаются на месте, так как хранятся в PostgreSQL.
- Перезапустить frontend.
  - Ожидаемо: данные не теряются.
- Перезапустить backend-контейнер без удаления volume PostgreSQL.
  - Ожидаемо: данные не теряются.
- Выполнить logout/login.
  - Ожидаемо: пользователь снова видит свои данные и доступные разделы.

## 20. Негативные и граничные сценарии

- Открыть детальную страницу с несуществующим UUID проекта/работника/сметы/отчёта/инструмента.
  - Ожидаемо: показывается ошибка загрузки или 404, приложение не падает.
- Ввести очень длинные строки в поля названия, комментария и описания.
  - Ожидаемо: UI не ломается, backend либо сохраняет допустимое значение, либо возвращает валидационную ошибку.
- Ввести отрицательные значения в часы, бюджет, ставку, сумму расхода и лимит использований.
  - Ожидаемо: форма или backend отклоняет некорректные значения.
- Быстро нажать кнопку сохранения/отправки несколько раз.
  - Ожидаемо: не создаются дубли или кнопка блокируется на время запроса.
- Проверить мобильную ширину экрана.
  - Ожидаемо: нижняя навигация, карточки, формы и фильтры остаются удобными и не выходят за экран.
- Проверить тёмную тему там, где она поддержана worker-экранами.
  - Ожидаемо: текст остаётся читаемым, важные статусы различимы.
