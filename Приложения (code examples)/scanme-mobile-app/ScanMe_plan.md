Привет! Проект ScanMe выглядит очень актуально и имеет хороший потенциал. Я подготовил для тебя подробный план, который охватывает ключевые технические и бизнес-аспекты.

### 📚 Варианты публичных баз данных по штрих-кодам

Вот несколько сервисов, которые лучше всего подходят для твоей задачи:

**1. Open Food Facts (рекомендуемый вариант)**

Это одна из крупнейших в мире открытых краудсорсинговых баз данных продуктов питания. Является лучшим выбором для MVP (минимально жизнеспособного продукта):

*   **Покрытие:** Более 4 миллионов продуктов питания по всему миру.
*   **Данные:** Предоставляет подробные сведения о продукте: название, бренд, состав (`ingredients_text`), пищевую ценность, включая список добавок (`additives_tags`).
*   **API:** Бесплатный REST API с форматом ответа JSON.
    *   **Пример запроса:** `https://world.openfoodfacts.org/api/v0/product/{barcode}.json`
*   **Преимущества:** Открытая лицензия, что упрощает работу. Для Flutter существует официальный пакет `openfoodfacts` на pub.dev, который упрощает интеграцию с API.

**2. Barcode Lookup (коммерческий вариант)**

Хорошая коммерческая альтернатива с более структурированными данными:

*   **Покрытие:** База данных насчитывает миллионы товаров (не только продукты питания).
*   **API:** Платный REST API с посуточной оплатой.
*   **Преимущества:** Подходит, если нужны данные о непищевых товарах (бытовая химия, косметика, электроника), так как база не ограничивается продуктами питания.

**Другие варианты для изучения:**

*   **Icecat API:** Крупный каталог с описаниями товаров (включая электронику), может быть полезен для поиска данных по EAN/UPC/GTIN.
*   **barcodes catalog (RapidAPI):** Еще одна база данных по GTIN с составом и пищевой ценностью.

### 📱 План приложения ScanMe (Flutter + Material Design)

#### 1. Ключевые функции приложения

*   **Сканирование:** Быстрое и точное сканирование штрих-кодов EAN-13, UPC, QR через камеру.
*   **Анализ состава:** Мгновенная обработка данных: получение состава из базы данных и его анализ на вредные вещества.
*   **Объяснение вреда:** Четкое и простое объяснение, почему конкретный компонент считается опасным.
*   **История:** Хронология всех сканирований для быстрого доступа к ранее проверенным продуктам.
*   **Избранное:** Возможность сохранять товары для быстрого сравнения.
*   **Подписка:** Управление лимитами сканирований (3 бесплатных скана в день, далее — платная подписка).

#### 2. Архитектура Flutter-приложения

*   **Чистая архитектура:** Рекомендую разделить код на слои: **Data** (работа с API и БД), **Domain** (бизнес-логика) и **Presentation** (UI) для облегчения поддержки и тестирования.
*   **State Management:** Для реактивного обновления UI можно использовать `flutter_bloc` или `riverpod`.
*   **Навигация:** `go_router` для гибкой настройки маршрутов и deep linking.
*   **Ключевые пакеты Flutter:**
    *   `mobile_scanner` (или `barcode_scan2`): Для интеграции сканера.
    *   `openfoodfacts`: Для работы с базой данных Open Food Facts.
    *   `http` или `dio`: Для сетевых запросов.
    *   `hive` или `sqflite`: Для локального хранения истории сканирований.
    *   `purchases_flutter`: Для интеграции встроенных покупок (подписки).

#### 3. Интеграция с GPT и базой знаний

**Твой собственный «Справочник вредных веществ»**
Это key-value база данных (например, Firebase Firestore или локальный SQLite), которая хранит статьи о вредных веществах. Структура может быть такой:

```json
{
  "id": "E621",
  "name": "Глутамат натрия",
  "category": "Усилитель вкуса",
  "danger_level": "Спорный",
  "description": "Официально признан безопасным, но у некоторых людей может вызывать головную боль и другие симптомы.",
  "source": "Ссылка на научную статью"
}
```

**Интеграция с GPT (OpenAI API)**
Анализ состава продукта будет проходить в несколько этапов:
1.  **Получение данных о продукте** (по штрих-коду).
2.  **Локальный поиск:** Приложение сразу ищет каждый ингредиент в твоей базе знаний для мгновенного отображения информации.
3.  **GPT-анализ:** Отправка состава в GPT API для получения структурированных данных о вреде каждого компонента.
4.  **Агрегация результатов:** Объединение данных из локальной базы и ответа GPT для формирования итогового отчета.

Пример промпта для GPT API:

> "Ты — эксперт по химическому составу продуктов. Проанализируй следующий состав продукта: [список ингредиентов]. Найди в нём потенциально опасные или вредные вещества. Для каждого найденного вещества верни JSON-объект в формате, как в примере. Если вещество не найдено в твоей базе знаний, просто укажи его название."

#### 4. Дизайн и пользовательский опыт (UX/UI)

*   **Тёмная тема в Material Design 3:**
    *   Используй `ThemeData.dark()` в сочетании с `colorSchemeSeed` для создания гармоничной цветовой палитры.
    *   Цветовые акценты — например, ярко-зеленый (`Colors.greenAccent`) — можно использовать для кнопки сканирования или индикаторов опасности.
    *   Для вдохновения можно посмотреть на этот [референсный проект](https://github.com/Hash-Studios/qr-scanner-flutter) с реализованным тёмным режимом и Material Design.

*   **Экраны приложения:**
    *   **Главный экран (Сканер):** Доминирует видоискатель камеры с рамкой сканирования. Есть кнопка для переключения между сканированием штрих-кода и QR-кода и иконки для перехода в историю и настройки.
    *   **Экран результата:** Отображает фото и название продукта, под ним — общая оценка опасности (например, «Безопасен», «Спорный», «Опасен»). Далее следует подробный список ингредиентов, где нажав на компонент, можно развернуть краткое объяснение его влияния на организм.
    *   **Экран истории:** Список ранее отсканированных товаров с датой, оценкой и миниатюрой.
    *   **Экран оплаты:** Показывает преимущества подписки (безлимитные сканирования, отсутствие рекламы, ранний доступ к новым функциям) и предлагает оформить её.

#### 5. Монетизация (Freemium модель)

3 бесплатных сканирования в день — отличная модель для привлечения пользователей.

*   **Управление лимитами:** Локальный счётчик сканирований, сбрасываемый каждый день.
*   **Экран подписки:** Экран должен появляться при превышении лимита, четко донося ценность платной версии.
*   **Типы подписок:** Ежемесячная, годовая (со скидкой) и, возможно, пожизненная лицензия.

    *   Улучшенный дизайн (Material 3, тёмная тема, анимации).
*   **Будущие версии:**
    *   **Социальная сеть:** Возможность делиться результатами анализа.
    *   **Диетические профили:** Персонализированные рекомендации по питанию (аллергии, диета).
    *   **Анализ по фото:** Распознавание состава с этикетки, если штрих-код отсутствует или не читается.
